# v38.0: MiniMax-H3-X2-Detail-VAE on 8 GB: 2× Frames in +2 Seconds, and the Dark-Image Trap

> Date: 2026-10-04 · GPU: RTX 5060 Laptop 8GB · CUDA: cu132 · Framework: ComfyUI 0.37.0 (`--lowvram`) + MiniMax-H3 INT8 ConvRot · OS: Windows 11 native
> Release: https://github.com/Ultramanmao/ai-pipeline-local/releases/tag/v38.0

**TL;DR:** A 5.25 GB VAE add-on (MiniMax-H3-X2-Detail-v1) ships 2× frame resolution **at decode time** — 1664×960 native output for **+2 seconds** on a 265-second generation, versus **3–4 minutes** for a RealESRGAN x4 post-pass: roughly **100× cheaper**, with natural skin/hair/fabric where super-resolution gives you plastic. Its second mode (first-frame detail enhancement feeding I2V) is real too — high-frequency energy up +30–50% in the tail of the clip at zero cost. But it is **not free everywhere**: on dark, high-contrast images the enhancement at strength 1.0 crushes blacks and kills highlights (the same setting scores 8.5/10 on a bright scene). The production recipe that survived all tests: **X2 2× decode + `MiniMaxH3LatentSharpen` 0.2 globally; enhancement strength by content (bright 1.0 / dark 0.3 / unsure 0.3 or skip); RealESRGAN demoted to non-H3 material and background-critical shots.** Full A/B data, the single-variable discipline that caught a confounder, and the ComfyUI API trap that returns a bare 400 included.

---

## 1. The Question

We render vertical talking-head and character video on an 8 GB laptop. Delivery target is 1664×960. Until now the last mile was super-resolution: generate at 832×480, then run RealESRGAN x4 + LANCZOS downscale over all 124 frames. It works, it costs **3–4 minutes per clip**, and on people it produces exactly the look we keep failing review for — plastic skin, hardened hair edges, sharpening halos.

On 2026-09-30 an experimental HuggingFace drop crossed our radar: `speach1sdef178/MiniMax-H3-X2-Detail-VAE`, a 5.247 GB / 604-tensor VAE add-on for MiniMax-H3 with two claimed capabilities:

- **Mode 1 — decode-time 2× upscale** (PixelShuffle ×2 inside the VAE decode path)
- **Mode 2 — reference/first-frame detail enhancement** (an early-layer B32 pathway that pushes detail into the generated clip)

"Experimental" in the model card, no published benchmarks. So we ran one: single-variable A/B against our own production chain, same seed, same prompt, same everything except the one thing under test.

## 2. What We Installed

| Component | Detail |
|---|---|
| VAE add-on | `MiniMax-H3-X2-Detail-v1.safetensors` — 5.247 GB, 604 tensors, hf-mirror download, header-verified |
| Node pack (Mode 2) | `ComfyUI-H3-X2-Detailed` → `MiniMaxH3X2DetailedUpscale` (detail_strength 0–1.5) |
| Node pack (Mode 1) | `TripleHeadedMonkey/ComfyUI-MiniMaxH3_LatentUpscaler` → `MiniMaxH3VAEDecodeFast` |
| Base generation | `minimax_h3_fl2va_pruned_int8_convrot` + `qwen3vl_32b_nvfp4_awq` encoder + Turbo LoRA `turbo_v4_step600` @ 1.0 |
| Schedule | Beta, 6 steps, 832×480, 124 frames @ 24 fps (5.17 s), seed 42 |
| Super-resolution baseline | RealESRGAN ×4 + LANCZOS downscale → 1664×960 (our standing production chain) |

Test prompt (identical in every run): `a woman stands in a sunlit kitchen holding a coffee cup, natural light, photorealistic`

**Single-variable discipline:** every comparison changes exactly one thing. Mode 2 A/B changes only the presence of the enhancement node on the first frame. Mode 1 C/D changes only the decode path — the sampling chain is byte-identical and inherits A's prompt/seed/params. This discipline is what caught the confounder in Section 5.

## 3. Mode 2 — Detail Enhancement → I2V (A vs B)

A = raw first frame. B = same frame through `MiniMaxH3X2DetailedUpscale` (strength 1.0) before FL2V. Both clips generated at seed 42.

| Metric | A — raw first frame | B — enhanced first frame |
|---|---|---|
| Generation time | 265 s | **258 s** (zero overhead — the enhancement is a pre-pass) |
| Visual check @ t2.5 | 2/10 (motion blur mush) | **8/10** |
| High-frequency energy, 10-sample curve | avg 4.05 | avg 4.34; **tail +30–50%** (7.62 vs 6.18 at the back half) |
| Low-motion frame @ t4.2 | window buildings smeared | **roof tiles readable, near-sharp/far-soft improves, no artifacts** |
| File-size evidence (smoke test still) | 455,994 B | 1,905,353 B (~4× high-frequency content) |

**Verdict: the mode is real.** Detail from the enhanced first frame survives into the rendered clip, distant structure gets cleaner, and the cost is zero — it happens before generation starts. Two caveats, honestly:

- **Minor artifacts**: slight hand-edge deformation and label micro-warping at t2.5. Acceptable at delivery resolution.
- **The confounder** (next section).

## 4. The Confounder — Same Seed Is Not Same Motion

B moved **33% less** than A (optical-flow magnitude 15.04 vs 20.07). Enhancing the conditioning image changed the motion dynamics — same seed, diverging trajectory. That makes the spectacular t2.5 gap (2/10 vs 8/10) partially confounded: a less-blurred clip is easier to score sharp.

We did not throw the result out, and we did not wave it through. We re-judged on two evidence sources that are *not* contaminated by motion amount:

1. **High-frequency energy curve across 10 timestamps** — the tail gap (+30–50%) persists in later frames where both clips are settling.
2. **A matched low-motion moment (t4.2)** — same content, both nearly static: B shows readable roof tiles and better near/far separation, with zero artifacts.

Both independent measures agree with the visual check. Lesson written into our testing rules: **a single frame cannot decide an A/B when the treatment changes motion** — you need a motion-invariant measure plus a matched-motion frame.

## 5. Mode 1 — 2× Decode (C) vs RealESRGAN (D)

Same seed, same prompt, same sampling chain as A. The only difference is how the frames become pixels:

- **C**: `MiniMaxH3VAEDecodeFast` with the X2 VAE → 1664×960 **native**, tiling 256/64, temporal tiling off
- **D**: standard 832×480 decode → RealESRGAN ×4 → LANCZOS down to 1664×960

| Metric | C — X2 2× decode | D — RealESRGAN ×4 |
|---|---|---|
| Output resolution | **1664×960 native** | 1664×960 (via 3328×1920) |
| Extra time | **+2 s** (265 → 267 s) | **~3–4 min** (124 frames @ 0.7 fps + recompose) |
| Background zone | texture slightly soft, **no checkerboard artifacts** | **sharper** — but fake detail, plastic sheen, sharpening halos |
| Person zone | **decisive win** — skin, hair strands, fabric read as natural | plastic skin, hardened edges, uncanny sharpened face |
| Temporal consistency | native coherence (frame-consistent by construction) | per-frame SR, flicker risk inherent |
| Flicker metric vs source | **0.955** (spike 2.47 < 2.95) ✅ PASS | 0.996 ✅ PASS |

Time math: 2 seconds against 3–4 minutes is **~100×**. And even running the decode chain alone later (sampling cached) is 42 s versus 3–4 min for the SR chain — still 5×+.

**Verdict: split decision, and the split is useful.** C wins on truth, speed, faces, and time. D still wins raw edge acuity on background/small objects. For a person-facing pipeline (talking heads, character work) the person zone decides it — we moved the main line to X2 decode.

## 6. But the Background Is Soft — `MiniMaxH3LatentSharpen`

The node pack ships a latent-space sharpen node, so we ladder-tested it on the same decode path:

| Setting | Result |
|---|---|
| **E1: amount 0.2 / radius 1.0** | **Sweet spot.** Background acuity approaches RealESRGAN *without the fake* — no halos, no grain, no white edges. Person zone clean. |
| E2: amount 0.5 / radius 1.5 | Overshot — halos, grain, white edges (the exact "fake" look RealESRGAN gives), skin grainy. Rejected. |

**Production recipe lands here: X2 2× decode + LatentSharpen 0.2.** True + fast + sharp, all three, with no uncanny pass over faces.

## 7. The Dark-Image Trap (the expensive lesson)

Everything above was validated on bright, natural-light content. Then we ran the enhancement on a real production asset: a **dark, high-contrast composite** (transition-pipeline anchor frame) at strength 1.0.

It **crashed** — blacks crushed, highlights lost, edges smeared, overall contrast damaged. The exact setting that scored **8.5/10 on the bright kitchen still**.

The strength ladder on the dark frame:

| Strength | Dark high-contrast image | Bright natural image |
|---|---|---|
| 0.3 | **safe** — 95%+ contrast retained + micro-detail | subtle gain |
| 0.5 | degradation starts (lifted shadows, softened highlights, smeared edges) | good |
| 1.0 | **forbidden** — crush/loss/smear | **8.5/10** |

Also noted: Mode 2's node output is 1664×960 (it upscales 2× internally); feeding it back into an 832×480 first-frame input auto-downscales, and the detail still transfers (that is what Section 3 measured).

**Production rule, written down:** enhancement strength is a *content* decision — bright natural scenes 1.0, dark/high-contrast composites 0.3, unsure → 0.3 or skip. Nothing in a model card would have told you this; it cost us a production frame to find.

## 9. Pitfalls (all four cost real time)

1. **ComfyUI API submits: `required` parameters with defaults must still be sent explicitly.** `MiniMaxH3VAEDecodeFast` silently requires `temporal_tile_frames` / `context_frames` / `seam_warning_threshold`; omitting them returns a bare **HTTP 400** with no useful message. The *only* diagnosis path is the 400 response body's `node_errors` field. Send every required field even when the UI shows a default.
2. **Unzipped custom-node packs can pollute `custom_nodes/`.** A zip without a top-level directory drops `__init__.py` straight into the root — it may import, but it is a landmine. Always re-home into a subdirectory.
3. **ffmpeg `image2` output patterns must not contain dots** in the filename stem (`mot_A_1.0_%d.png` fails *silently*). Use underscores: `mot_A_1_0_%d.png`.
4. **A/B judging is forbidden at a single timestamp** when the treatment changes motion dynamics (§4). Motion-invariant measure + matched-motion frame, or the result is decoration.

## 10. Honest Limits

- **This is an H3-decode-path tool.** Non-H3 material (old footage, photos, other models' output) still needs conventional upscaling. Super-resolution is demoted, not dead.
- **2×, not 4×.** If you need 3328×1920 delivery, stack another stage on top.
- **Background/acuity-critical work keeps RealESRGAN.** Architecture, product shots, small-object legibility: D's raw sharpness still wins, halos and all.
- **The enhancement is content-sensitive** (§7). We validated exactly two brightness regimes; the 0.3/1.0 rule is an empirical ladder from one dark asset and one bright asset, not a law of nature. Treat "unsure" as 0.3 or skip.
- **Model is labeled experimental** and Mode 2's treatment of motion dynamics (§4) is undocumented upstream.

## 11. What We Learned

1. **Decode-time upscale beats post-hoc upscale on faces by construction** — the 2× detail is synthesized by the VAE's own generative prior, so skin/hair/fabric land natural. Post-hoc SR only sharpens whatever pixels exist, artifacts included. ~100× time difference is almost a side note.
2. **Zero-overhead features still need A/B.** Mode 2's pre-pass "costs nothing," so the temptation is to skip testing. The dark-image crash (§7) is what a skipped test looks like.
3. **A treatment that changes motion confounds every visual judgment downstream.** We caught it because the motion numbers looked too good; we resolved it with a motion-invariant metric. Same-seed is a starting point, not a control.
4. **Sweet-spot ladders beat defaults.** 0.2 sharpen, 0.3 dark enhance — both are one notch away from the shipped default and both only showed up in a ladder test.
5. **When a ComfyUI node returns a bare 400, read the response body.** `node_errors` is the only truth source; the UI and the logs will not tell you which field you omitted.

## 12. What's Next

- Test the enhancement ladder on mid-key content to firm up the 0.3/1.0 boundary.
- Try `MiniMaxH3LatentSharpen` between 0.2 and 0.5 for a sharper-but-clean background class.
- Apply Mode 2 to reference-image-driven work (RefMod / R2V first frames) where a crisp identity reference should sharpen character detail transfer.

**Summary: decode-time 2× gives an 8 GB laptop 1664×960 H3 video in +2 seconds with faces that look real — super-resolution keeps only the shots that need its kind of sharpness.**
