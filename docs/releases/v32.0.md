# v32.0: Building a 7,000-Asset AI Library With a Three-Layer Review Pipeline

> Old Mao's Local AI Engineering Notes · 2026-09-14
>
> How I built a self-hosted asset library that uses rule engines, perceptual hashing, and MiMo-2.5 Vision to curate 7,000+ AI-generated images, videos, and audio files — with a human-in-the-loop Web UI and an undo system.

---

## 1. The Problem

Every local AI pipeline produces artifacts. Flux generates images, H3 generates videos, CosyVoice generates audio. After a few months of active use, I had 7,000+ files scattered across output directories, with no way to find what was good, what was garbage, and what was worth reusing.

The manual approach doesn't scale. Even at 3 seconds per image, reviewing 7,000 files takes 6 hours of pure clicking — and you still can't remember which seed produced that perfect lighting setup three weeks ago.

I needed a system that could:
- Ingest files automatically as pipelines produce them
- Score quality without human intervention (first pass)
- Detect duplicates across directories
- Use vision AI to evaluate actual image content
- Let a human make final decisions, not the AI
- Remember what was decided and learn from it

---

## 2. The Architecture

Three layers, each filtering what reaches the next:

```
Files on disk
  │
  ├─ L1: Rule Engine (zero cost, milliseconds)
  │   ├─ File health: corrupt, empty, unreadable
  │   ├─ Image quality: blur (Laplacian), brightness, resolution
  │   ├─ Video quality: resolution, bitrate, duration
  │   ├─ Black frame detection: 5 sampled frames, >60% = reject
  │   └─ Metadata completeness: model/prompt/seed/steps/cfg
  │
  ├─ L2: Deduplication (low cost, seconds)
  │   ├─ pHash perceptual hashing (Hamming distance <6 = exact)
  │   ├─ Filename dedup (same name across directories)
  │   └─ [planned] CLIP semantic dedup (cosine >0.95)
  │
  └─ L3: Multimodal AI Review (API call, ~15s/image)
      ├─ MiMo-2.5 Vision: quality score, defects, aesthetics
      ├─ Prompt match: does the image match its generation params?
      ├─ Reuse value: 11 categories (cover, b-roll, reference, etc.)
      ├─ NSFW detection: auto-isolate with password protection
      └─ Human feedback loop: learn from past overrides
```

The stack:

| Component | Role | Tech |
|-----------|------|------|
| Database | Asset metadata, generation params, audit log | SQLite (WAL mode) |
| API Server | REST endpoints, file serving, thumbnails | Python ThreadingHTTPServer, port 8191 |
| Watchdog | Auto-import new files from output dirs | File system watcher |
| Frontend | Review + Browse pages | Static HTML, CSS waterfall, vanilla JS |
| AI Backend | Vision/audio scoring | MiMo-2.5 via API |

## 3. Step-by-Step Walkthrough

### 3.1 Database Schema

Three core tables connected by a relation table:

```sql
-- The asset itself
CREATE TABLE asset (
    id TEXT PRIMARY KEY,          -- IMG-20260910-00586
    type TEXT,                    -- IMG / VID / AUD / LAT
    name TEXT,
    path TEXT,

    duration_sec REAL,            -- for VID/AUD

    description TEXT,

    ai_score REAL,                -- L3 MiMo score (1-10)
    ai_review_json TEXT,          -- full MiMo response
    phash TEXT,                   -- perceptual hash
    sensitive INTEGER,            -- NSFW flag
    sensitive_reason TEXT,
    human_action TEXT,            -- keep / reject (from human override)
    human_reason TEXT,
    deleted_at TEXT               -- soft delete
);

-- One AI generation run
CREATE TABLE generation (
    id TEXT PRIMARY KEY,
    model TEXT,
    prompt TEXT,
    negative TEXT,
    seed INTEGER,
    steps INTEGER,
    cfg REAL,
    sampler TEXT,
    scheduler TEXT,
    reuse_score REAL,
    reuse_tags TEXT
);

-- Links assets to generations
CREATE TABLE relation (
    generation_id TEXT,
    output_asset_id TEXT,
    input_asset_id TEXT,          -- for i2i / reference
    role TEXT
);

-- Operation log for undo
CREATE TABLE asset_changes (
    id INTEGER PRIMARY KEY,

```

IDs use a readable format: `{TYPE}-{YYYYMMDD}-{XXXXX}`. Not UUIDs — you can tell what something is from the ID alone.

### 3.2 L1: Rule Engine

Zero API calls. Every file passes through this first.

**Image quality** uses three signals:

```python
def assess_image_quality(path):
    img = cv2.imread(path)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    
    # Blur: Laplacian variance (threshold 50)
    blur_score = cv2.Laplacian(gray, cv2.CV_64F).var()
    
    # Brightness: mean pixel value (50-200 = ok)
    brightness = gray.mean()
    
    # Resolution: anything below 256px is flagged
    h, w = img.shape[:2]
    
    # Weighted composite: blur(40%) + brightness(30%) + resolution(30%)
    return compute_score(blur_score, brightness, w, h)
```

**Video quality** uses ffprobe:

```bash
ffprobe -v error -show_entries stream=width,height,bit_rate \
  -show_entries format=duration -of json video.mp4
```

Thresholds: <720p resolution, <2 Mbps bitrate, <1s or >600s duration = reject.

**Black frame detection** samples 5 frames evenly across the video. Each frame is read with PIL, converted to grayscale, and checked:

```python
mean = numpy.array(frame).mean()
if mean < 10:    # black frame
if mean > 245:   # white frame
# >60% bad frames → reject
```

**Metadata completeness** scores how much generation info is available:

| Field | Weight | Why it matters |
|-------|--------|---------------|
| model | 0.30 | Can't reproduce without knowing the model |
| prompt | 0.30 | Can't learn from or reuse the prompt |
| tags | 0.15 | Can't search for it |
| seed | 0.10 | Can't reproduce exact output |
| steps | 0.10 | Affects quality |
| cfg | 0.05 | Fine-tuning parameter |

### 3.3 L2: Perceptual Hashing

pHash (16×16 DCT, low-frequency extraction, median binarization) produces a 256-bit hex fingerprint. Hamming distance comparison:

| Distance | Meaning | Action |
|----------|---------|--------|
| < 6 | Near-exact duplicate | Auto-reject |
| 6-10 | Similar image | Flag for human review |
| > 10 | Different | Pass |

For 7,000 assets, brute-force comparison of all pairs takes ~3 seconds. No need for FAISS at this scale.

```python
from PIL import Image
import numpy as np

def compute_phash(path, hash_size=16):
    img = Image.open(path).convert('L').resize((hash_size, hash_size))
    pixels = np.array(img, dtype=np.float64)
    dct = np.fft.dct(np.fft.dct(pixels, axis=0), axis=1)
    low_freq = dct[:hash_size//2, :hash_size//2]
    median = np.median(low_freq)
    return (low_freq > median).flatten().tobytes().hex()

def hamming_distance(h1, h2):
    return bin(int(h1, 16) ^ int(h2, 16)).count('1')
```

### 3.4 L3: MiMo-2.5 Vision

The expensive layer. Each image gets sent to MiMo-2.5 with a structured JSON prompt asking for:

1. **Content description** — what's in the image (20 chars max)
2. **Quality score** — 1-10 (blur, artifacts, resolution)
3. **Defect list** — extra fingers, broken faces, garbled text, deformed objects
4. **Prompt match** — 1-10 (does the image match the generation parameters?)
5. **Aesthetic score** — 1-10 (composition, lighting, color)
6. **NSFW flag** — boolean
7. **Reuse value** — 11 categories: cover, b-roll, reference, style_ref, character_ref, scene_ref, color_ref, composition_ref, texture, background, face_ref
8. **Prompt quality** — 1-10 (is the generation prompt itself worth saving?)
9. **Technique notes** — reusable prompt tricks (lighting keywords, negative prompt hacks)

The response is a single JSON object stored in `ai_review_json`. Key insight: **disable thinking mode** in MiMo. Without it, the reasoning tokens consume the entire output budget and you get an empty response.

```python
payload = {
    "model": "mimo-v2.5",
    "messages": [{"role": "user", "content": [
        {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
        {"type": "text", "text": REVIEW_PROMPT}
    ]}],
    "thinking": {"type": "disabled"},   # CRITICAL: without this, output is empty
    "max_tokens": 4096,                 # not 1024 — the JSON schema is large
    "response_format": {"type": "json_object"}
}
```

### 3.5 Decision Flow

```
L1 file_health not ok → reject
L1 quality_score < 30 → reject
L2 pHash distance < 6 → reject
L3 ai_score < 5 → reject
L3 ai_score 5-7 → low-confidence keep (human reviews)
L3 ai_score ≥ 8 → high-confidence keep
L3 nsfw = true → mark sensitive (password-protected, not deleted)
```

AI never auto-deletes. It proposes. A human confirms.

### 3.6 The Web UI

Two pages, both static HTML served by the same API server:

**Review Page (`/`)** — staging assets only. AI proposals rendered with color-coded borders: green = keep, red = reject, yellow = uncertain. Per-card ✓/✗ buttons for human override. Batch selection with checkboxes.

**Browse Page (`/browse`)** — all assets. 4-column CSS waterfall layout with infinite scroll (IntersectionObserver). Each card shows:
- Thumbnail (200px, disk-cached)
- AI score badge (🤖 8.5 — green ≥8, yellow 6-8, red <6)
- Name, type, file size

Click a card → detail panel slides in from the right:
- Full preview (image/video/audio playback)
- AI audit tags: score, aesthetics, prompt quality, defect count, NSFW flag
- Content description from AI
- Reuse value categories and tags
- Defect list (red-highlighted)
- Prompt technique notes (green-highlighted)
- Inline tag/description editing
- Quick action buttons: save, pass, delete, mark as cover/b-roll/reference
- AI suggest button (sends context to MiMo for real-time analysis)

### 3.7 Undo System

Every mutation (status change, tag edit, delete) logs the old value to `asset_changes` before executing:

```python
def log_change(asset_id, field, old_value, new_value, action):
    conn.execute(
        "INSERT INTO asset_changes (asset_id, field, old_value, new_value, action, created_at) "
        "VALUES (?, ?, ?, ?, ?, ?)",
        (asset_id, field, str(old_value), str(new_value), action, datetime.now().isoformat())
    )
```

Undo reads the last N changes and reverses them. Batch operations log per-item, so batch-delete can be undone one by one. Ctrl+Z shortcut on both pages.

### 3.8 Human Feedback Learning

When a human overrides an AI decision (keeps something AI wanted to reject, or vice versa), the system records `human_action`, `human_reason`, and `human_reviewed_at`. On the next AI review pass, the system reads the last 20 human decisions and injects them into the MiMo prompt:

```
Recent human decisions for reference:
- IMG-20260910-00123: AI said reject (score=4), human kept. Reason: "good composition despite blur"
- VID-20260910-00045: AI said keep (score=9), human rejected. Reason: "boring content"
```

The flywheel: more human decisions → richer context → better AI suggestions → less human intervention needed.

### 3.9 Sensitive Content Protection

NSFW assets are not deleted — they're isolated:

1. AI detects NSFW → sets `sensitive=1`, `sensitive_reason="AI detected: NSFW"`
2. Browse page: sensitive assets hidden by default (`WHERE sensitive=0`)
3. Lock icon in toolbar → password prompt → unlock (sessionStorage, tab-scoped)
4. Unlocked: sensitive assets show 🔞 badge, file endpoints accessible
5. Close tab → locked again

Backend returns 403 for sensitive assets without the password query parameter. Password is configured in `config.py`.

## 4. The Biggest Pitfall

**Python f-strings eating HTML attributes.**

The entire frontend is generated by Python f-strings in `review_page.py` and `browse_page.py`. The template builds HTML cards like:

```python
f'<img class="thumb" src="{API}/api/thumb/{a["id"]}" />'
```

This works fine until you need JavaScript string literals inside HTML attributes. The classic trap:

```python
f'onerror="this.outerHTML=\'<div>No Preview</div>\'"'
```

Python parses `\'` as an escaped single quote inside the f-string, which is correct for Python. But the HTML output has raw `'` characters inside a double-quoted attribute, which browsers interpret as attribute delimiters. The entire `<script>` block after this point becomes part of the `onerror` attribute value. Every JavaScript function silently stops working.

**What we tried:**

| Approach | Result |
|----------|--------|
| `\'` escaping | Breaks HTML attribute parsing |
| `\\'` double-escape | Produces `\'` in output — browsers hate it |
| `&apos;` entity | Doesn't work in HTML attributes |
| Event delegation | Works perfectly |

**The fix:** Stop using inline event handlers entirely. Use data attributes + event delegation:

```html
<!-- In the template — clean, no escaping -->
<img class="thumb" data-preview-id="IMG-20260910-00586" 
     data-preview-type="IMG" src="/api/thumb/IMG-20260910-00586" />
```

```javascript
// In the script section — event delegation
document.getElementById('cardList').addEventListener('click', function(e) {
    var el = e.target.closest('[data-preview-id]');
    if (el) {
        openPreview(el.dataset.previewId, el.dataset.previewType);
    }
});
```

This pattern survived every edge case: Chinese characters in IDs, special characters in paths, and dynamic content loaded via infinite scroll.

## 6. What We Learned

1. **Rule engines catch 60-70% of bad files before spending a single API credit.** Black frames, corrupt files, and sub-256px images don't need a vision model to judge. Layer your review — free checks first, expensive AI last.

2. **pHash is underrated at this scale.** For <50K assets, brute-force Hamming distance comparison is fast enough. No need for FAISS or approximate nearest neighbor. The 16×16 DCT catches cropped, resized, and recompressed duplicates that filename matching misses.

3. **Disable MiMo's thinking mode for structured output.** Without `"thinking": {"type": "disabled"}`, the model spends all its output tokens on reasoning and returns empty content. This cost me two hours of debugging.

4. **`.format()` and JSON prompts don't mix.** Python's `str.format()` interprets `{` and `}` in JSON schemas as placeholders, raising `KeyError`. Use `.replace('{placeholder}', value)` instead.

5. **Event delegation beats inline handlers for generated HTML.** Every inline `onclick`/`onerror` in Python-f-string-generated HTML is a ticking time bomb of escaping issues. Data attributes + container-level listeners survive everything.

6. **Undo is not optional.** The first time a user batch-deletes 50 assets by accident, they'll thank you for the `asset_changes` table. Log before executing, not after.

7. **AI confidence matters more than AI score.** An image with `ai_score=9` but `confidence=low` (because it has no generation metadata) should not be auto-approved. The confidence field decides whether to auto-act or queue for human review.

8. **The human feedback flywheel works, but slowly.** After 20-30 human overrides, the AI starts noticing patterns (e.g., "this user values composition over sharpness"). But the effect is subtle — don't expect dramatic improvements from a handful of corrections.

9. **SQLite is fine for this.** 7,000 assets with FTS5 full-text search, perceptual hash comparison, and concurrent read/write from three processes (API, watchdog, batch reviewer). WAL mode handles it all. No need for PostgreSQL until you hit 100K+ assets.

10. **Thumbnails need a dedicated endpoint, not inline generation.** Generating base64 thumbnails in the browse API response kills page load time. A separate `/api/thumb/{id}` endpoint with disk caching (JPEG @ 200px, 7-day Cache-Control) makes the waterfall layout feel instant.

## 7. What's Next

- **CLIP semantic dedup** — pHash catches pixel-level duplicates but misses "same scene, different angle." CLIP embeddings (512-dim) with cosine similarity >0.95 would catch these.
- **Batch AI review automation** — the current `batch_ai_review.py` loops through staging assets in batches of 100. Needs better crash recovery and progress persistence.
- **Prompt template library** — the `generation` table already stores prompts with `reuse_score` and `reuse_tags`. Building a searchable prompt template browser would turn the asset library into a prompt knowledge base.
- **Multi-library support** — separate libraries for different projects (video production, Xiaohongshu content, character design) with cross-library search.
