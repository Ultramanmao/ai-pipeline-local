# v45.0: A Four-Season Video Loop on 8 GB — 4 × 3.75 s at 24 GPU-Min per Segment, and the Green-Leaf-in-Snow Trap

> Old Mao's Local AI Engineering Notes · 2026-10-16
>
> One-sentence hook: a single-variable test proves season-change video transitions fail for a physics reason, not a prompt-length reason — endpoint interpolation never draws an event like falling leaves, and one beat-sentence block flips a judged-fail clip into a closed four-season loop on an 8 GB RTX 5060 laptop card.

---

## 1. The Goal / Problem

Transition prompt templates are everywhere: "hold the composition, change only the season, cut at the peak of the action." We picked one — the environment-transformation template (fixed camera, fixed building, season changes around a walking figure) — and did what the template said, exactly.

The result was judged fail on sight: **a winter scene with a maple tree in full green leaf wearing a cap of snow, and green grass under the snow.** The template was followed to the letter. The physics was wrong.

The root cause is structural. Our pipeline (like most first/last-frame video chains) generates a clip that interpolates *appearance* between two anchor frames: a summer state and a winter state. "Leaves turn yellow, then fall one by one, then branches go bare" is a sequence of **events**. Endpoint interpolation has two end states and no notion of events in between — so it decorates the endpoints (green leaves + snow both "look like winter/summer features") and never draws the process.

So the real question of this build:

> Can a prompt force physically-ordered events (turn → fall → bare → wither → snow) inside a state-interpolating model — and how do you prove which sentence did the work?

The answer is one block of ordered beat sentences, verified by a single-variable A/B, and it shipped as a closed loop: **summer → autumn → winter → spring → summer**, 4 segments × 3.75 s = 15 s, with the last segment closing back onto the first segment's anchor image so the loop is seamless by construction.

## 2. The Stack / Architecture

All local, one 8 GB laptop GPU (RTX 5060, shared with other work — jobs run only when the GPU is idle).

| Component | Tool | Role |
|---|---|---|
| Anchor stills | Qwen-Image 2.1 (t2i + edit chain) | Four same-composition season states at 1344×768: summer A, autumn B2, winter C2, spring D3 |
| Video engine | FreeVideo `fl2va` task, two-pass (8-step base + 3-step refine) | 90 frames @ 24 fps = 3.75 s per segment, first/last frame anchors |
| Physics prior | `wushu_spatial_physics_clean_3000_pruned` LoRA @ 0.3 | Spatial/physics regularization, kept low so it doesn't repaint style |
| Assembly | FFmpeg concat | Segment chain + loop close |
| QC | tail-freeze check, frame sheets, anchor PSNR | Pass/fail criteria written down *before* watching |

The organizing principle, learned the hard way:

> **Anchor pairs carry state. Beat sentences carry events.**

Each segment's prompt is exactly three parts:

1. **Environment sentence** — what must never change (camera, building, composition, the walking figure).
2. **Physics beat sequence** — the ordered event chain, with explicit ordering words.
3. **Invariant + closing clause** — end exactly on the tail anchor's state, never freeze early.

State differences (summer look vs winter look) live in the anchor images, not in the prompt. The prompt only manages *how* the model gets from one to the other.

## 3. Step-by-Step Walkthrough

### Step 1 — Build the anchor chain (states live here)

One summer manor still generated with Qwen-Image 2.1 t2i (stone manor, maple tree, gravel path, woman in a red coat), then three edit-chain derivations — autumn B2, winter C2, spring D3 — same composition, only the season state differs. QC on the anchors before any GPU video time is spent (camera/building/figure position, season state correctness, no artifacts): 6/6 for the first pair, 7/7 for the spring anchor.

The loop's trick: segment 4's tail anchor is segment 1's head anchor (back to summer A). Continuity at the seam is guaranteed by construction, not by luck.

Escape-hatch removal: if a beat is critical, bake it into the anchor. The grass-browning beat kept being ignored mid-chain, so the autumn anchor was regenerated **with the grass already dead and brown** — the model can't skip an event whose end state is already painted into the frame.

### Step 2 — Write the prompt as environment + ordered beats + invariants

Real prompt used for segment 1 (summer → autumn), verbatim:

```text
A single continuous shot with a completely fixed, static camera. The stone manor
house, the maple tree, the low stone garden wall, the gravel path and the entire
composition stay absolutely stable: the building's position and perspective never
change or warp, staying consistent with Picture 1 and Picture 2. A woman in a red
coat walks slowly and steadily along the gravel path in the foreground, moving
continuously at a constant pace throughout the whole shot. The season gradually
progresses from summer to autumn with a physically natural sequence: the maple
leaves turn from lush green to golden yellow and orange, then leaves detach one
by one and drift down to the ground, a layer of fallen leaves gathers on the lawn
and along the path edges, thin bare twigs appear among the thinning foliage, the
grass yellows and withers into dry patches, and the light shifts from warm high
summer sunlight to soft low autumn light. Leaves change color before they fall;
nothing turns white or snowy in this shot. The same exact manor architecture as
the reference images, same roof, same windows, no redesign. The change progresses
gradually until the final moment, ending exactly on the autumn scene matching
Picture 2 with the same viewpoint and composition; the scene never freezes early
and the woman keeps walking until the very end.
```

The beat block is the middle sentence. Note three devices that turned out to matter:

- **Explicit ordering**: "turn … then leaves detach one by one … a layer gathers … twigs appear … grass yellows" — a chain, not a pile of adjectives.
- **Negative scope clauses**: "Leaves change color before they fall; nothing turns white or snowy in this shot" — forbids the model from skipping ahead to the next segment's state.
- **Anti-freeze closing**: "the scene never freezes early and the woman keeps walking until the very end" — kills the common tail-freeze failure.

The winter segment (autumn → winter) is where the ordering words get aggressive, after the fix:

```text
… progresses from late autumn to deep winter with a strictly physical sequence in
this order: first all remaining golden leaves fall away until the maple branches
are completely bare, then the yellowed grass turns completely brown and dead
across the whole lawn, and only then snow arrives - dusting the bare branches and
roof first, then gradually burying the dead brown grass under a continuous white
layer, a few brown fallen leaves staying half-buried at the snow edges … Snow
arrives only after the leaves have fallen AND the grass has died; no green grass
appears anywhere once winter begins. …
```

"in this order", "first", "then", "only then", "Snow arrives only after … AND …" — the model will not infer causality; you have to write it as a script.

### Step 3 — Media manifest (anchors + LoRA)

```json
{
  "version": 1,
  "first": ".../A_tr03_anchorA_summer_00001_.png",
  "last":  ".../B2_tr03b_autumn_00001_.png",
  "loras": [{"path": ".../wushu_spatial_physics_clean_3000_pruned.safetensors",
             "strength": 0.3}]
}
```

One manifest per segment; `first`/`last` swap in the anchor pair for that segment.

### Step 4 — Generate (with the two guards that matter)

```bash
freevideo.cmd --root E:/WSL/FreeVideo generate --task fl2va \
  --prompt-file video_prompt_seg1.txt --media media_seg1.json \
  --width 1344 --height 768 --frames 90 --seed 20261018 \
  --cache "$CACHE" --out tr03b_seg1_summer_autumn.mp4
```

The run script is staged (`anchors | videos | concat`) because of two live failure modes:

- **anchors stage needs ComfyUI UP** (it drives Qwen-Image 2.1); **videos stage needs ComfyUI DOWN** — running the video engine while ComfyUI holds VRAM/RAM is a machine-killer (two real crashes before this became a hard gate in the script: it refuses to start if port 8188 is still listening).
- **Long GPU jobs must run detached.** One run was killed mid-sampling (step 7/11) by a foreground terminal timeout — the engine log showed no FAIL, just silence. Rerun detached with a fresh output filename and it went through. Never run 20+ minute GPU work in a session foreground.

Seeds are fixed per segment (20261018/19/20…) so a rerun is reproducible.

### Step 5 — Concat + QC

Plain FFmpeg concat of the four segment files. QC is judged against criteria written down before viewing:

1. Camera/building/perspective stable end to end (first/mid/last frame comparison).
2. Environment gradient continuous (green → yellow → fallen → snow), no jumps.
3. The red-coat walker keeps walking — no freeze, no vanish, no body swap.
4. No frozen tail (tail-freeze check: ≥ 1 s of static tail = fail).
5. Full frame, no mask bars or blurred edges.
6. Tail frame matches the tail anchor (PSNR reference).

Result: **all four segments pass**. Tail-staticity measured at 0.04 s (single test) and 0.09 s-class (cycle segments). Tail-anchor PSNR of 18.2 dB is *by design* — the figure walks to the last moment and snow is falling, so the last frame is not a static copy of the anchor; the anchor defines the state, not the pixels.

## 4. The Biggest Bug: Green Leaves Wearing Snow

Two judged-fail failures, one root cause.

**Failure 1 (single test, first take):** the winter half showed the maple in full green leaf with snow settled on the foliage. Following the template didn't help — the template says *what changes*, not *in what physical order*.

**Failure 2 (cycle segment 2):** leaves fell and branches went bare correctly, but the grass never browned — it went from green straight to buried under snow. Everything else passed; this one beat was skipped.

What we tried (single-variable where it counts):

| Variant | Prompt difference | Result |
|---|---|---|
| Template only (env sentence + invariant) | no beat block | ❌ green leaves wearing snow |
| Template + beat sentences | + ordered event chain | ✅ sequence renders in order |
| Beat sentence for grass, mid-prompt | grass mentioned, not ordered | ❌ grass skipped (seg 2 first run) |
| Beat block with hard ordering + baked anchor state | "in this order / only then", dead grass painted into the autumn anchor | ✅ grass browns before snow |

The fix that shipped is the seg-2 prompt quoted above plus one anchor change. **Attribution:** variants 1 and 2 differ only in the beat block — the flip from judged-fail to pass is on the beat sentences, nothing else.

The general lesson, in one line: **interpolation models render states; events must be written as ordered beats, and anything the model still skips must be painted into the anchor so there is no path around it.**

(Also in the bug column: the foreground-terminal timeout kill described in Step 4 — a 24-minute GPU job is not a foreground job.)

## 6. What We Learned

1. **States vs events is the whole game.** First/last-frame chains interpolate appearance. Seasons are a process. If you don't write the process as ordered beats, you get endpoint decoration — green leaves wearing snow.
2. **Ordering words are load-bearing**: "in this order", "first", "only then", "only after … AND …". A list of seasonal adjectives is not a sequence.
3. **Scope-guard the negatives**: "nothing turns white in this shot" stops the model from consuming the next segment's state early.
4. **Bake skipped states into the anchor.** If the model ignores a critical beat (grass browning), paint the end state into the tail anchor instead of adding more prompt words.
5. **Single-variable A/B or it's a guess.** Two prompt variants differing only in the beat block is the only reason we can claim the beat block is the fix.
6. **Write QC criteria before watching** (tail-freeze threshold, frame-comparison method, PSNR as reference not gate). Post-hoc criteria move toward whatever the clip did.
7. **Loops close by construction**: make the last segment's tail anchor the first segment's head anchor.
8. **24 GPU-min per 3.75 s segment** — budget before you run; a five-try search is two hours of GPU.

## 7. What's Next

- **Unresolved A/B:** "hard cut to" vs "switch to" wording inside a single generation — different engines treat "cut" semantics differently, untested here.
- **Event fidelity horizon:** how many seconds of ordered events a 90-frame clip can carry before beats start collapsing — no data yet.
- **Five of six templates untested:** only environment-transformation has been through the single-variable pipeline. Action match (peak-frame anchor pair) is next in line.
- The transition-archetype survey (17 categories across edit-language and prompt-template traditions) is catalogued; each future template gets the same small A/B before it earns GPU time.

## Summary

**Season transitions fail because endpoint interpolation paints states and skips events — write physics beats in enforced order, bake the stubborn states into the anchor pair, and a four-season loop runs 24 GPU-minutes per 3.75-second segment inside 6.0 GiB of VRAM.**
