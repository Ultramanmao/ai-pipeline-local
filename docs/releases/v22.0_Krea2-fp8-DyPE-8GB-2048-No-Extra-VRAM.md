# Krea2 fp8 + DyPE on 8 GB: 2048² in 135 Seconds, No Extra VRAM

## TL;DR

Krea2 fp8 normally caps at 1024² on an 8 GB card. DyPE (Dynamic Position Extrapolation) runs the entire diffusion process at base resolution inside latent space, then extrapolates to higher resolutions — meaning 2048×2048 costs the same VRAM as 1024×1024. SEGA (Spectral Energy Guided Attention) adds a second quality knob. Combined, they turn an 8 GB laptop into a 2048² image generator in 135 seconds. No post-upscale, no tiling, no extra GPU memory.

---

## The Problem: 1024² Is Not Enough

Every Krea2 fp8 workflow I had running hit the same wall: 1024×1024 output. For Xiaohongshu vertical covers (1080×1920), that means upscaling — and post-upscale always looks softer than native generation. Traditional latent upscale (2× → 2048²) requires double the VRAM for the KSampler step, which OOMs immediately on 8 GB.

The question was simple: **can Krea2 fp8 generate above 1024² on 8 GB without OOM?**

---

## DyPE: How It Works

DyPE (Dynamic Position Extrapolation) from wildminder/ComfyUI-DyPE (603★) doesn't upscale. It changes where the model "thinks" each token is positioned during attention computation.

Normal diffusion at 2048²: the model processes a 2048² latent → huge attention matrix → OOM.

DyPE at 2048²: the model processes a **1024² latent** but with extrapolated position embeddings that tell the attention layers "you're covering a 2048² region." The VRAM footprint stays at 1024² levels. The output quality depends on how well the position extrapolation generalizes — and for Krea2's Qwen-based text encoder + DiT architecture, it generalizes well.

**Key parameter:** `method: vision_yarn` — the recommended extrapolation method, robust across aspect ratios.

---

## SEGA: The Quality Multiplier

SEGA (Spectral Energy Guided Attention), added in DyPE v2.5.0 on 2026-08-04, injects a spectral energy signal into the attention computation. Think of it as a lightweight CFG alternative that improves coherence at higher resolutions without the VRAM cost of raising CFG.

**Key parameter:** `mscale_alpha: 0.15` (default, works well for Krea2).

## The Node Chain

```
UNETLoader (krea2_turbo_fp8_scaled, fp8_e4m3fn)
  ↓
LoraLoaderModelOnly (krea2_darkbrush, strength_model=0.8)
  ↓
CLIPLoader (qwen3vl_4b_fp8_scaled, type='krea2')
  ↓
DyPE (model_type=auto, method=vision_yarn, base_resolution=1024)
  ↓
SEGA (method=sega, mscale_alpha=0.15)
  ↓
KSampler (steps=8, cfg=1.0, sampler=euler, scheduler=normal)
  ↓
VAEDecode (qwen_image_vae)
```

ComfyUI must be at commit 76135e55 or later (Krea2 architecture support). `comfy_kitchen` must be ≥ 0.2.31.

## Resolution Benchmarks (8 GB RTX 5060 Laptop)

| Resolution | Time | File Size | VRAM Peak | Status |
|:---|:---:|:---:|:---:|:---:|
| 1000×1000 | 45 s | 1.6 MB | ~6.5 GB | ✅ |
| 1536×1536 | 70 s | 3.7 MB | ~7.0 GB | ✅ |
| **2048×2048** | **135 s** | **6.3 MB** | **~7.5 GB** | ✅ |

No manual VRAM management needed. ComfyUI's `--lowvram` flag handles the dynamic offload. The jump from 1536² to 2048² costs 65 extra seconds — roughly proportional to the pixel count increase (1.8× pixels → 1.9× time).

For comparison, traditional latent upscale (1024² → 2048² via KSampler) on the same hardware: **OOM at KSampler step** — the 2048² latent requires ~12 GB VRAM.

## Six Pitfalls

### 1. nvfp4 Is Dead on ComfyUI v0.24+

`krea2_turbo_nvfp4.safetensors` (7.15 GB) gets rejected by UNETLoader with "Could not detect model type." ComfyUI 0.24+ does not recognize the nvfp4 format. **Use fp8** (`krea2_turbo_fp8_scaled.safetensors`, 12.23 GB) — it's larger but actually loads.

### 2. CLIPLoader `type` Must Be `'krea2'`

The new `krea2` type was added in the same ComfyUI commit that supports Krea2 architecture (76135e55). Older ComfyUI versions only have `qwen_image`, which throws: "expects 12×2560=30720 features but got 2560." If you see this error, your ComfyUI is too old.

### 3. LoraLoaderModelOnly Uses `strength_model`, Not `strength`

The parameter name differs from the standard LoraLoader. Passing `strength=0.8` silently does nothing — the LoRA loads but doesn't apply. Use `strength_model=0.8`.

### 4. `comfy_kitchen` ≥ 0.2.31 Required

Newer ComfyUI depends on `int8_attention_is_available` from comfy_kitchen. Older versions crash at startup with an ImportError. Pin `comfy_kitchen>=0.2.31`.

### 5. VAE Misidentified as WAN Video

`qwen_image_vae.safetensors` can be misdetected as a WAN video VAE (shape[4] out of bounds) when the Krea2 CLIP type is wrong. Fix: ensure CLIPLoader uses `type='krea2'` — this tells ComfyUI's loader to expect the correct VAE shape.

### 6. Git Proxy Timeout on Large Repos

`git clone` and `gh repo clone` time out through the 29290 proxy for large transfers. Workaround: `gh api repos/{owner}/{repo}/tarball/master > file.tar && tar xf file.tar`. Slower but reliable.

## What DyPE Cannot Do

- **Arbitrary aspect ratios** — DyPE extrapolates from a square base resolution. Non-square outputs work but quality degrades beyond 2:1 aspect ratio.
- **Video** — DyPE is image-only. Each frame would need independent DyPE processing.
- **Replace real 2048² training** — extrapolated positions are an approximation. Fine detail (text at small font, thin lines) at 2048² is softer than a model natively trained at that resolution.
