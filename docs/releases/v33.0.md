## 1. The Goal / Problem

Every local AI pipeline that touches voice needs at least three separate tools: a TTS engine for speech generation, a noise reduction model for cleanup, and a voice separator for extraction. Each has its own Python environment, its own model weights, and its own quirks.

I was running CosyVoice2 for TTS, a separate noise reduction model, and yet another tool for voice separation. Three tools, three sets of dependencies, three things that can break.

Then Tencent Hunyuan released AuK on September 9, 2026 — a 1.5B-parameter speech foundation model that claims to do all of this through a single unified interface. One model, one API, one set of weights.

The question: can AuK actually replace three specialized tools, or is it another "jack of all trades, master of none"?

## 2. The Stack / Architecture

| Component | Role | Size |
|-----------|------|------|
| AuK (auk_base.safetensors) | Core DiT model | 5.8 GB |
| AuK VAE (vae.safetensors) | Audio VAE | 608 MB |
| Qwen2.5-Omni-3B | Text/audio encoder | 11.2 GB (3 shards) |
| RVC WebUI | Voice conversion | ~2 GB |
| PyTorch 2.7.1 (CPU) | Inference runtime | — |

Total disk: ~18 GB for AuK + encoder. RVC adds ~2 GB more.

```bash
.venv/Scripts/pip install -e ".[cpu]"  # or cuda variant
```

Download weights from HuggingFace:
```bash
# auk_base.safetensors (5.8 GB) + vae.safetensors (608 MB)
# → ckpts/AuK/
# Qwen2.5-Omni-3B (11.2 GB, 3 shards)
# → ckpts/Qwen2.5-Omni-3B/
```

### Step 2: Patch safetensors for Windows

Windows has a known mmap segfault when loading large multi-shard models. AuK uses safetensors internally, and the Qwen encoder's 11.2 GB across 3 shards triggers it.

The fix is a monkey-patch that switches to the `pread` backend:

```python
import safetensors, safetensors.torch

original_safe_open = safetensors.safe_open
def patched_safe_open(filename, framework, device='cpu', backend='mmap'):
    return original_safe_open(filename, framework, device=device, backend='pread')

safetensors.safe_open = patched_safe_open
safetensors.torch.safe_open = patched_safe_open
```

Reference: transformers issue #48285, PR #48341 (merged in transformers 4.57.6).

### Step 3: Run TTS

```python
from auk.infer.inference import AuKInference

model = AuKInference(model_path='ckpts/AuK', encoder_path='ckpts/Qwen2.5-Omni-3B')

# Zero-shot TTS (voice cloning)
audio = model.tts(
    text="Hello, this is a test.",
    reference_audio="reference.wav",  # 3 seconds is enough
    output_path="output.wav"
)

# Instruct TTS (no reference audio needed)
audio = model.tts(
    text="用温柔撒娇的语气说：欢迎回来宝宝",
    output_path="output_cn.wav"
)
```

```
│  AuK        │     │  RVC        │     │  Output     │
```

Three use cases:

|----------|----------|
| Song voice swap | AuK vocal separation → RVC voice conversion → merge back |
| Any voice says anything | AuK TTS generation → RVC voice conversion |
| Edit + swap | AuK speech editing (change one word) → RVC voice conversion |

## 4. The Biggest Bug / Pitfall

### The safetensors mmap segfault

This one cost me 2 hours. AuK's Qwen encoder loads 3 shards totaling 11.2 GB. On Windows, safetensors uses mmap by default, which maps all shards into virtual memory simultaneously. With other GPU processes running, the system's commit limit gets exhausted, causing a silent segfault (exit 139) during `from_pretrained`.

The error message was useless — just "Process finished with exit code 139". No traceback, no Python exception.

What I tried:

| Approach | Result |
|----------|--------|
| Increase page file | Helped but didn't fix it |
| Kill GPU processes | Reduced commit usage, still segfaulted |
| Load shards one at a time | Not supported by transformers |
| Patch safetensors to use pread | ✅ Fixed it |

The `pread` backend reads file data sequentially instead of memory-mapping it. Slightly slower loading, but no commit pressure.

### The page file exhaustion

Even with the pread patch, loading 11.2 GB of model weights requires significant commit space. If ComfyUI or other GPU processes are running, the system runs out of memory.

**Fix**: Close all GPU processes before loading AuK. After killing ComfyUI, available commit went from ~23 GB to 53 GB — plenty for the encoder.

## 6. What We Learned

1. **One model can replace three** — AuK's unified interface for TTS + enhancement + separation eliminates the need for multiple specialized tools. The quality is good enough for production use.

2. **Instruct TTS is the killer feature** — Being able to say "用温柔撒娇的语气" and get exactly that emotion is more intuitive than tweaking parameters. No reference audio needed.

3. **Voice editing saves retakes** — Changing one word in a recorded narration without re-recording the entire segment is a massive time saver for content creators.

4. **Windows is still a second-class citizen** — The safetensors mmap segfault is a known issue (transformers #48285) but not yet fixed in the default install. The pread patch works but feels fragile.

5. **CPU inference is viable for batch work** — 3 minutes per segment is slow, but for batch content creation (e.g., generating 10 narration segments overnight), it's acceptable.

6. **RVC fills AuK's gap** — AuK can't do voice conversion (changing existing audio to sound like someone else). RVC handles this perfectly and runs in real-time on GPU.
