# v39.0: RefMod on 8 GB: A 9.5 KB Character Concept Scores 80.8% Where a Full Reference Image Scores 20%

> Date: 2026-10-04 · GPU: RTX 5060 Laptop 8GB · CUDA: cu132 · Framework: ComfyUI 0.37.0 (`--lowvram`) + MiniMax-H3 INT8 ConvRot · OS: Windows 11 native
> Release: https://github.com/Ultramanmao/ai-pipeline-local/releases/tag/v39.0

**TL;DR:** We ran a four-way character-consistency shootout on MiniMax-H3 with one reference photo, one seed (42), and vision-scored output frames: **RefMod identity concept + a styling prompt hit 80.8%** feature retention, the no-reference baseline got 35%, and the model's *native* reference pathway (Ref2VA with an exact "reproduce exactly" instruction) scored **dead last at 20%**. The surprise is not that a 9.5 KB / 48-token concept file works — it is that the flagship reference feature, given the actual photograph, is the worst of the four at locking wardrobe and hair. The division of labor that emerged: **RefMod locks who the face is, the prompt locks what the character wears, and a full reference image locks neither.** Render cost is unchanged (~5 min/segment on 8 GB, Turbo 6-step). Small accessories remain unsolved (a flower hairpin was lost in 5/5 runs). Full scoring table, node-graph wiring notes, and the follow-up production hardening (step-curve direction, multi-photo consensus extraction, motion LoRA for camera moves) included.

---

## 1. The Question

Character consistency is the make-or-break problem for story video: same person, shot after shot. MiniMax-H3 offers three plausible answers on this hardware, and we had never measured them against each other:

1. **RefMod** — extract a lightweight identity concept from a photo (`MiniMaxH3RefModExtract` → tiny `.safetensors`), inject at generation time
2. **Native R2V reference** — the Ref2VA pathway with `<Picture 1>` plus a "reproduce exactly" consistency pin: the model sees the actual photograph
3. **Baseline** — text prompt only, no reference at all

Conventional wisdom says the model looking at the real photo should win. We ran the numbers.

## 3. The Four Arms

| # | Arm | Identity source | Styling prompt |
|---|---|---|---|
| 1 | RefMod + styling prompt | RefModApply, identity strength 1.0 | **full** — hairstyle/dress/accessories written out |
| 2 | RefMod, no styling | RefModApply, identity strength 1.0 | generic: "young woman with long dark hair" |

Arms 2–4 deliberately share the *generic* prompt so the only variable in the headline comparison (arm 1 vs the rest) is what each system can do with the same words. Arm 1 exists to answer the practical question: once you know RefMod holds the face, how much do you gain by also writing the outfit?

## 4. Results (vision-scored frames, first 0.5 s)

| Feature | RefMod + styling | RefMod bare | R2V native | Baseline |
|---|---|---|---|---|
| Dark-brown low bun + strands | **95%** | 0% (loose hair) | 0% (loose hair) | 0% (loose hair) |
| Oval face | **98%** | 100% | 100% | 50% |
| Warm light skin tone | **97%** | 100% | 100% | 100% |
| Beige embroidered dress | **99%** | 0% (white shirt) | 0% (blue shirt) | 0% (grey top) |
| Pearl drop earrings | **96%** | 0% | 0% | 0% |
| White magnolia hairpin | **0%** | 0% | 0% | 0% |
| **Composite** | **80.8%** | 50% | **20%** | 35% |

Ranked: **RefMod+styling 80.8% > RefMod bare 50% > baseline 35% > R2V native 20%.**

Read that last row again: giving the model the actual photograph with an explicit "reproduce exactly" instruction performed **worse than not referencing anything** on composite scoring. The face layer transferred (100% oval face, 100% skin tone — R2V's face metrics are fine); everything above the face collapsed to the same failure as a bare prompt.

## 5. What Is Actually Going On

Three findings, each actionable:

**1. RefMod + styling prompt is the golden combination (80.8%) — the two lock different layers.** RefMod carries face identity (hair color, face shape, skin tone: 95–98%); the prompt carries costume and styling (dress 99%, earrings 96%). Neither alone is sufficient: RefMod bare loses the entire wardrobe layer (0% dress), and no arm that skips the styling prompt keeps the outfit.

**2. The reference pathway is identity-shallow.** R2V with the full photo nails face geometry and then discards everything the photo says about styling — hair, dress, accessories all 0%, statistically identical to having no reference. An instruction like "reproduce exactly" does not extend the reference's authority below the face. If your consistency requirement includes wardrobe (ours does — the dress is a character signature), the native reference path is not delivering it.

**3. Small accessories are the universal blind spot.** The white magnolia hairpin: **0% in every arm, 4/4**. Even the 80.8% arm loses it. Whether this is tokenizer attention dilution or training-data rarity, a tiny accessory is not reliably carried by any current mechanism — it needs either a dedicated clothing/props RefMod or explicit negative+positive prompt weight, and we have not solved it yet.

## 6. The Production Stack (what we adopted)

| Layer | Tool | Job |
|---|---|---|
| Style / motion | LoRAs (Wushu 0.5 / Spatial 0.3 / Realism 0.6) | motion vocabulary, texture |
| Identity / character | **RefMod** (identity, strength 1.0) | face, hair color, skin tone |
| Costume / details | **prompt** | hairstyle, dress, accessories |

Render cost: RefMod single-reference ~4–5 min/segment with Turbo 6-step on 8 GB — same ballpark as a plain FL2V segment. The concept file is 9.5 KB, so shipping a character between projects is a file you can paste into a chat message.

## 7. Node-Graph Notes (the wiring that matters)

- **Extract**: `MiniMaxH3RefModExtract`, `concept_type` = **`identity`** (not `character`); the `vae` input must be wired **inside the inputs dict** or the extraction silently produces garbage
- **Apply**: `ImageToVideo.positive → RefModApply → BasicGuider` — inject after the positive conditioning is built, before the guider
- **Serialized keys use dot notation** (`refs_image.ref_image_0`), same autogrow convention as R2V
- **Multiple references**: `MiniMaxH3RefModsLoader` has 8 slots. Two RefMod refs under `--lowvram` costs real time — **~35 min/segment** (weight shuffling dominates)
- **Step curve**: `MiniMaxH3RefModStepCurve` sits between the TurboLoRA apply and the Scheduler

## 8. Follow-up Production Hardening (2026-10-04 runs)

After the shootout we took RefMod through two real production segments (transition-chain work). Findings that are not in the comparison data but change how you wire it:

- **`curve_direction` must be `constant`.** `concept_at_end` halves the effective identity strength late in the denoise — the face drifts back toward the model prior in the back half of the clip. (Same class of trap as FL2V first/last-frame anchoring: the tail drifts to prior unless held.)
- **Multi-photo consensus extraction: `merge=True` on Extract.** Feeding several reference photos with merge produces one consensus anchor; per-photo extraction gives you per-photo quirks.
- **Loader takes bare names** — no paths, no extensions.
- **Camera moves need their own LoRA.** Prompt-only arc/orbit moves largely fail on this stack; `camera_motion_h3_lora_v1_3000_pruned` @ 0.6 (via `LoraLoaderModelOnly`) is what makes them land.
- **Motion QC rule: compare two frames from the same take** (early + late, composed side by side). Single-frame review misjudges motion work constantly — a still cannot show whether the move happened.

## 9. Benchmarks (all arms, same machine, same seed)

| Arm | Identity source | Time / segment | Composite score |
|---|---|---|---|
| RefMod + styling prompt | 9.5 KB concept | ~5 min (Turbo 6-step) | **80.8%** |
| RefMod bare | 9.5 KB concept | ~4 min | 50% |
| R2V native reference | full photo | ~6 min (no Turbo path for ref2va) | 20% |
| Baseline | none | ~5 min | 35% |
| RefMod ×2 (multi-ref) | 2 concepts | ~35 min (`--lowvram`) | not scored |

Note the R2V arm's ~6 min: the ref2va path has **no Turbo acceleration route**, so the "obvious" reference approach is also the slowest — the worst-scoring arm costs 50% more per segment.

## 10. Honest Limits

- **Vision scoring is semi-quantitative.** Feature-retention percentages come from frame inspection against the reference checklist, not a learned metric. The spread (80.8 vs 20) is far outside scorer noise; the exact decimals are not.
- **One character, one photo, one seed.** A single-seed comparison shows the mechanism clearly but is not a distribution. The production runs (§8) were consistent with it.
- **Accessories unsolved.** The 0/5 hairpin is a real gap, not a rounding artifact.
- **Double RefMod cost is untested for quality** — we measured the 35-minute cost, not whether two concepts actually beat one.
- **`concept_type=identity` vs `character`**: we standardized on `identity` after extraction behaved inconsistently with `character`; we did not run a formal comparison of the two modes.

## 11. What We Learned

1. **A bigger reference is not a stronger reference.** The 33-GB-class pipeline looking at a full-resolution photo lost to a 9.5 KB concept file on every non-face feature. Reference authority has a layer boundary (the face), and nobody advertises where it is.
2. **Consistency is a stack, not a knob.** Identity (RefMod), styling (prompt), motion (LoRA) — three layers, three tools. Asking one mechanism to carry all three is where the 20% came from.
3. **"reproduce exactly" is not a contract.** Natural-language consistency pins bind the layer the model already treats as identity. Costume and props need structural help.
4. **Test the layer you care about.** R2V's face metrics looked perfect (100%/100%) — if we had scored faces only, R2V would have "won."
5. **Cheap artifacts travel.** A 9.5 KB identity file that you can commit, message, and version is a workflow upgrade independent of quality: character continuity across projects becomes a file-management problem instead of a re-training problem.

## 12. What's Next

- Dedicated clothing/props RefMod for the accessory blind spot (the hairpin test is our new acceptance case)
- Multi-photo consensus extraction (`merge=True`) formally scored against single-photo extraction
- `concept_type=identity` vs `character` head-to-head
- Two-concept RefMod quality measurement (does 35 min buy anything?)

**Summary: lock the face with a 9.5 KB RefMod concept and write the outfit into the prompt — the native reference image pathway, counterintuitively, locks the least.**
