# v26.0: 40-Second Continuous H3 Video on 8GB GPU via Motion Context

> Old Mao's Local AI Engineering Notes · 2026-08-31
>
> One-sentence hook: Chained 8 H3 clips into a 40-second continuous video on an 8GB RTX 5060 using Motion Context — no Ref2VA model needed.

---

## 1. The Goal / Problem

H3 (MiniMax-H3) generates stunning video+audio in a single pass, but hard-limits at 15 seconds (362 frames). For any real content — music videos, short films, product demos — you need 30-60 seconds minimum.

The community offered two solutions:
- **Sampler-Unlimited (HREndlessSampler)**: Requires Ref2VA model (19.5GB). OOM on 8GB GPU.
- **Simple ffmpeg concat**: Works, but color drift accumulates at every join. Audio restarts instead of continuing.

Neither worked for our hardware. We needed a solution that:
1. Runs on 8GB VRAM (INT8 ConvRot + CPU offload)
2. Preserves color across clips (no decode/re-encode round-trip)
3. Continues audio naturally (not re-synthesized)

## 2. The Stack / Architecture

| Component | File | Size | Role |
|-----------|------|------|------|
| Diffusion Model | `minimax_h3_fl2va_pruned_int8_convrot.safetensors` | 19.5GB | FL2VA (First+Last Frame to Video) |
| Text Encoder | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` | 15.7GB | 32B NVFP4, CPU offloaded |
| Turbo LoRA | `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors` | 1.82GB | **NOT USED** — breaks chaining |
| Video VAE | `minimax_h3_video_vae_fp16.safetensors` | 4.9GB | Decode video latents |
| Audio VAE | `minimax_h3_audio_vae_fp32.safetensors` | 578MB | Decode audio latents |
| **Motion Context** | `ComfyUI-H3-Motion-Context` (custom node) | — | Latent-level clip chaining |
| SageAttention | `PathchSageAttentionKJ` (KJNodes) | — | Attention acceleration |

**Key insight**: Motion Context operates in **latent space**. It slices the previous clip's tail directly from its latent tensor — no pixel decode, no re-encode. The pinned frames are bit-for-bit identical to the original generation.

## 3. Step-by-Step Walkthrough

### Step 1: Install Motion Context

Adds 4 nodes:

- `H3 Motion Context Trim` — removes pinned head from output
- `H3 Motion Context Save Latent` — saves AV latent to disk (safetensors)
- `H3 Motion Context Load Latent` — loads AV latent from disk

### Step 2: Generate Clip 1 (Standard I2V + Save Latent)

```json
{
  "1": {"class_type": "CLIPLoader", "inputs": {"clip_name": "qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors", "type": "minimax"}},
  "2": {"class_type": "UNETLoader", "inputs": {"unet_name": "minimax_h3_fl2va_pruned_int8_convrot.safetensors", "weight_dtype": "default"}},
  "2b": {"class_type": "PathchSageAttentionKJ", "inputs": {"model": ["2", 0], "sage_attention": "auto"}},
  "8": {"class_type": "MiniMaxH3ImageToVideo", "inputs": {
    "clip": ["1", 0], "vae": ["4", 0],
    "prompt": "A woman walks gracefully along a sunlit city street...",
    "width": 576, "height": 768, "length": 125,
    "first_frame": ["6", 0],
    "turbo_mode": false
  }},
  "10": {"class_type": "BasicScheduler", "inputs": {"model": ["2b", 0], "scheduler": "beta", "steps": 20, "denoise": 1.0}},
  "18": {"class_type": "MiniMaxH3MotionContextSaveLatent", "inputs": {"latent": ["12", 0], "filename_prefix": "h3_context/clip", "clip_index": 1}}
}
```

**Critical**: `turbo_mode: false`, `scheduler: "beta"`, `steps: 20`. Turbo LoRA destroys chain continuity.

### Step 3: Generate Clip 2 (Load Latent → Motion Context → Trim)

```json
{
  "20": {"class_type": "MiniMaxH3MotionContextLoadLatent", "inputs": {"latent_path": "h3_context", "clip_index": 1}},
  "21": {"class_type": "MiniMaxH3MotionContext", "inputs": {
    "conditioning": ["8", 0],
    "vae": ["4", 0],
    "latent": ["8", 1],
    "context_length": "22",
    "audio_context_length": 24,
    "context_latent": ["20", 0]
  }},
  "9": {"class_type": "BasicGuider", "inputs": {"model": ["2b", 0], "conditioning": ["21", 0]}},
  "32": {"class_type": "MiniMaxH3MotionContextTrim", "inputs": {
    "images": ["14", 0],
    "trim_frames": ["21", 1],
    "audio": ["15", 0],
    "fps": 24.0
  }}
}
```

**Parameters**:
- `context_length: "22"` — pins 22 frames (~0.92s) from previous clip. Options: 5/22/39/56.
- `audio_context_length: 24` — pins 24 audio frames (~1s) for audio continuity.
- `clip_index: 1` — loads Clip 1's saved latent.

### Step 4: Concatenate

```bash
echo "file 'clip1.mp4'" > list.txt
echo "file 'clip2.mp4'" >> list.txt
ffmpeg -f concat -safe 0 -i list.txt -c copy chain.mp4
```

No re-encoding needed — same resolution, codec, fps.

### Step 5: Repeat for N clips

Each continuation clip:
1. Load previous clip's latent (`clip_index: N-1`)
2. Motion Context modifies conditioning
3. Generate with 20 steps + beta scheduler
4. Trim pinned head
5. Save latent for next clip (`clip_index: N`)

## 4. The Biggest Bug / Pitfall

### Turbo LoRA Destroys Chain Continuity

**Symptom**: Clips generated with 8-step Turbo LoRA show:
- Slow-motion feel (actions appear stretched)
- Visible pause at seam (22-frame pinned head creates a "stuck" moment)
- Audio discontinuity at joins

**What we tried**:

| Approach | Steps | Scheduler | LoRA | Result |
|----------|-------|-----------|------|--------|
| Fast mode | 8 | simple | Turbo | ❌ Slow-motion, seam pause |
| Medium | 20 | simple | Turbo | ❌ Better but still janky |
| **Correct** | **20** | **beta** | **None** | **✅ Smooth, natural** |

**Root cause**: The Turbo LoRA (lightx2v 8-step distillation) makes large per-step changes. When Motion Context pins 22 frames from a non-Turbo generation, the Turbo sampler's denoising trajectory diverges, creating a visible discontinuity.

**Fix**: Disable Turbo LoRA entirely. Use native 20-step sampling with beta scheduler. Each clip takes ~6 minutes instead of ~3.5 minutes, but continuity is perfect.

### Prompt Continuity Matters More Than Action Magnitude

**Discovery**: Testing 8 clips with varying action intensities:

| Transition | Action Change | Continuity |
|-----------|---------------|------------|
| Walk → Wave | Small | ✅ Perfect |
| Wave → Walk | Small | ✅ Perfect |
| Walk → Look back | Medium | ✅ Good |
| Look back → Smile walk | Medium | ✅ Good |
| **Run → Jump spin** | **Large (upward+rotation)** | **⚠️ Visible jump** |
| **Jump spin → Squat** | **Large (downward)** | **✅ Surprisingly good** |

**Insight**: Physical continuity > action magnitude. Jumping "breaks" the Motion Context trajectory because it introduces vertical+rotational motion that doesn't exist in the previous clip's latent. Squatting works because it's a continuous downward motion in the same plane.

**Prompt template**:
```
The woman [continues previous action], then [new action]. [Details]. Same street, same dress. Cinematic, 4k
```

Use "continues/then/smoothly". Never use "suddenly/abruptly".

## 6. What We Learned

1. **Turbo LoRA is incompatible with Motion Context** — the distillation trajectory diverges from the pinned latent frames. Always use native 20-step sampling for chaining.

2. **FL2VA works fine** — no need for Ref2VA model. The community's Sampler-Unlimited requires Ref2VA, but Motion Context doesn't.

3. **context_length=22 is the sweet spot** — 5 frames is too short (abrupt transitions), 39 frames creates a slow-motion feel. 22 frames (~0.92 seconds) provides enough overlap for smooth continuation without excessive pinned frames.

4. **Prompt design is critical** — each clip's opening action must continue from the previous clip's ending action. Physical continuity (same plane of motion) matters more than action magnitude.

5. **2-clip chains are most stable** — 3+ clip chains accumulate drift. For longer videos, consider 2-clip segments joined with ffmpeg crossfade.

6. **Latent file naming is tricky** — `clip_index` on Load Latent must match the Save Latent's `clip_index`. Mismatched indices load wrong clips (tested: loaded stone statue instead of walking woman).
