# v27.0: H3 vs LTX-2.3 — Video Pipeline Showdown on 8GB GPU

> Old Mao's Local AI Engineering Notes · 2026-09-06
>
> Two video diffusion pipelines, one 8GB RTX 5060, five test cases. LTX is 8x faster, but H3 owns long video and native audio. Here are the numbers.

---

## 1. The Goal / Problem

You have an 8GB GPU and want to generate video locally. Two serious open-source options exist:

- **MiniMax H3** (INT8 ConvRot): 20-step sampling, native audio generation, Motion Context for chaining clips into 40-60 second videos. But each 5-second clip takes 7 minutes.
- **LTX-2.3** (distilled GGUF Q4_K_M): 8-step distilled sampling, blazing fast at 3 minutes per clip. But no native long-video chaining, and audio requires a separate AV pipeline.

Which one should you bet on? The community mostly vibes on "H3 for quality, LTX for speed" — but nobody had run them head-to-head on identical hardware with identical prompts. We did.

## 2. The Stack / Architecture

| Component | H3 INT8 ConvRot | LTX-2.3 distilled |
|-----------|-----------------|-------------------|
| Diffusion Model | `minimax_h3_fl2va_pruned_int8_convrot` (20GB) | `ltx-2.3-22b-distilled-1.1-Q4_K_M` (14GB) |
| Text Encoder | `qwen3vl_32b_minimax_h3_nvfp4_awq` (15.7GB, CPU offloaded) | `gemma-3-12b-it-qat-UD-Q3_K_XL` + text_projection |
| Steps | 20 (native) | 8 (distilled) |
| Sampler | `res_multistep` + `simple` scheduler | `euler` |
| CFG | 1.0 | 1.0 |
| Resolution | 832×480 / 512×768 / 576×768 | 512×768 (max) |
| Frame Rate | 24 fps | 24 fps |
| Audio | Native (audio VAE, 578MB) | AV pipeline (`LTXAVTextEncoderLoader`) |
| Long Video | Motion Context (40-60s) | ❌ Single segment only |
| VRAM Peak | ~7.5 GB | ~6 GB |
| ComfyUI Nodes | `MiniMaxH3ImageToVideo` | `LTXVImgToVideo` |

**Key architectural difference**: H3 bundles audio generation into the same diffusion pass — the model outputs video and audio latents simultaneously. LTX can do this too, but requires a specific node chain (`LTXAVTextEncoderLoader` → `LTXVConcatAVLatent` → sampler → `LTXVSeparateAVLatent`) that most tutorials skip.

### Step 2: Define 5 Test Cases

| Case | Scene | Purpose |
|------|-------|---------|
| 1 | Japanese garden, cherry blossoms, golden hour | Static baseline (image quality) |
| 2 | Woman walking in park, white dress | Human motion quality |

### Step 3: Run H3 (20 steps, beta scheduler)

```json
{
  "class_type": "MiniMaxH3ImageToVideo",
  "inputs": {
    "prompt": "A serene Japanese garden with a koi pond...",
    "width": 832, "height": 480, "length": 121,
    "turbo_mode": false
  }
}
```

**Critical**: `turbo_mode: false`. The Turbo LoRA (8-step distillation) breaks chain continuity — tested and confirmed in v26.0.

### Step 4: Run LTX (8 steps, euler)

```json
{
  "class_type": "LTXVImgToVideo",
  "inputs": {
    "positive": "...", "negative": "...",
    "image": "...", "width": 512, "height": 768,
    "length": 121, "strength": 0.7
  }
}
```

**Note**: The correct I2V node is `LTXVImgToVideo`, not `LTXVImgToVideoAdvanced` (which doesn't exist despite being referenced in some docs).

### Step 5: For LTX Audio, Use the AV Pipeline

```json
LTXAVTextEncoderLoader (text_encoder + embeddings_connectors, device=cpu)
→ LTXVEmptyLatentAudio (audio VAE)
→ LTXVConcatAVLatent (video + audio latents)
→ Sampler
→ LTXVSeparateAVLatent
→ VAEDecode (video) + LTXVAudioVAEDecode (audio)
→ CreateVideo + SaveVideo
```

**Common mistake**: Using `DualCLIPLoaderGGUF` + `EmptyLTXVLatentVideo` — this outputs video only, no audio. You must use the AV-specific nodes.

### Step 6: Compare

Extract frames at 1.25s / 2.5s / 3.75s, stack side-by-side:

```bash

ffmpeg -i ltx.mp4 -vf "select=eq(n\,60)" -vframes 1 ltx_frame_060.png
ffmpeg -i h3_frame_060.png -i ltx_frame_060.png \

```

## 4. The Biggest Bug / Pitfall

### LTX Audio: The Missing Pipeline

**Symptom**: LTX generates silent video. No errors, no warnings — just no audio track.

**What we tried**:

| Approach | Nodes Used | Result |
|----------|-----------|--------|
| Default I2V | `DualCLIPLoaderGGUF` + `EmptyLTXVLatentVideo` | ❌ Video only, no audio |
| Add audio VAE | Same + `EmptyLTXVLatentAudio` | ❌ Still no audio (wrong latent type) |
| Concat manually | `LTXVConcatAVLatent` before sampler | ⚠️ Crashes (missing embeddings_connectors) |
| **Full AV pipeline** | **`LTXAVTextEncoderLoader` + AV nodes** | **✅ Audio + Video** |

**Root cause**: LTX's audio generation requires a specific text encoder configuration. `DualCLIPLoaderGGUF` loads the video text encoder only. `LTXAVTextEncoderLoader` loads both the text encoder AND the audio embeddings connectors — a separate component that conditions the audio latent space.

**Fix**: Always use `LTXAVTextEncoderLoader` when you need audio. Set `device=cpu` to avoid VRAM conflicts with the video pipeline.

### H3 Resolution: 432×768 Doesn't Exist

**Symptom**: ComfyUI crashes with reshape error when using 432×768.

**Fix**: H3's valid resolutions are 832×480, 512×768, 576×768, 384×1056. Stick to these. The model's latent space has fixed aspect ratio buckets.

## 6. What We Learned

1. **Speed gap is consistent**: 8× across all test cases. LTX 3 min vs H3 7 min per 5-second clip. This doesn't narrow with complex scenes — it's baked into the step count.

2. **Quality gap only appears beyond 5 seconds**: For short clips, the difference is negligible. H3's advantage shows in long-video chaining (Motion Context) and color saturation.

3. **LTX audio works, but the pipeline is obscure**: Most LTX tutorials skip audio entirely. The `LTXAVTextEncoderLoader` → `LTXVConcatAVLatent` chain is the correct path, but it's poorly documented.

4. **H3's native audio is a workflow advantage**: One node, one pass, audio+video. No separate encoder, no latent concatenation, no sync issues. For any project where audio matters, this saves 30+ minutes of debugging.

5. **VRAM headroom favors LTX**: 6 GB vs 7.5 GB. On an 8 GB GPU, that 1.5 GB difference means LTX can coexist with other tools (TTS, image generation) while H3 needs exclusive access.

6. **Resolution flexibility favors H3**: 4 aspect ratio buckets vs LTX's single 512×768. For Xiaohongshu vertical video (9:16), H3's 576×768 is a better starting point.
